# AI 分镜校对 Skill

这是一个帮你检查 AI 预演视频的 Skill。

它会把视频和你的分镜脚本、人物图、场景图、道具图放在一起对照，检查：

- 画面是不是演对了脚本
- 前后镜头的人物、服装、位置和道具是否接得上
- 有没有漏镜、乱序、错误转场或多出剧情

最后给你一份带小分镜图的 Markdown 报告，方便直接阅读和修改。

问题达到返修条件时，这个版本会另给你一份新视频提示词，供你自行生成。Skill 到提示词交付为止，不调用 API，也不会自动付费生成视频。

## 你需要准备什么

最少准备三类东西：

1. 一段已经生成的 AI 智能镜头视频
2. 按顺序写好的分镜脚本，最好带镜号、画面内容、动作、结果和时长
3. 相关资产图，例如人物、场景、道具和关键状态图

如果你还留着**生成这段视频时用的原提示词**，也可以一并提供（直接粘贴，或给 TXT/MD 文件）。没有也能正常审查。

也可以提供已经确定的 **Shot 分组**，例如 `A01：S01–S03；A02：S04–S06`，支持文字、表格或 JSON。提供就按你的分组检查和省图，不再自动拆组、合组；没有则沿用自动分组。

## 它会怎么工作

1. 检查文件是否齐全，并给视频建立可追溯的时间和画面指纹。
2. 抽帧并按镜号对照脚本和资产图。
3. 分三层检查：单个镜头、相邻镜头、整段故事。
4. 逐镜记录检查结果和依据。允许的小差异会说明为什么不影响剧情；看不清的地方会说明缺什么证据、该补看哪里。
5. 保留原镜头编号和顺序，在你指定的分组内判断参考图取舍；没有指定时，自动合并同一剧情段里的相邻镜头。合格组计划时长为 4–15 秒、最多 12 镜。
6. 输出 Markdown 报告和小分镜图。
7. 达到返修条件时，参考脚本、原资产及可选原提示词，检查全部镜头后输出新视频提示词并停止。清楚的内容直接保留，有歧义或冲突才整理，不反复重写。

## 输出什么

你会得到：

- `01_原视频审查.md`：原视频的审查结果
- `images/`：报告中使用的小分镜图
- 一张逐镜表：保留分组编号、镜号、镜头时长、脚本、小图、检验结果和处理建议，不再另列分组关系表
- 达到返修条件时，另有 `新视频提示词/G01_新视频提示词.md`：按“资产对应 → 逐镜脚本 → 固定预演要求 → 资产风格”排列，可直接复制；每镜可保留必须／不得出现，不附标题、参数表、路径或代码块

每个镜头都会保留。确认漏镜后，会标出“必要漏镜”，或在证据充分时建议“可推导生成”。
原视频里已经有、并且审查通过的镜头，即使建议省去独立参考图，也会保留抽帧缩略图和原图链接；只有确认漏镜且通过省图判断时，才显示“可推导生成”文字，不伪造图片。

## 什么时候输出新视频提示词

每份输入视频单独判断，满足任一条件就输出新视频提示词：

- 1 镜出现有脚本和视频证据的关键剧情错误或关键节点缺失，例如认错行动主体、交接结果相反、因果断裂。
- 1 镜严重花屏、人物或关键道具损坏，导致必要动作无法辨认；须记录受损区间和被遮挡内容，轻微闪烁不算。
- 普通但影响剧情的已确认画面错误或漏镜，至少 2 镜且占该视频应覆盖镜头数的 20% 或更多。按原镜号去重；2/10 触发，2/11 和普通问题 1/3 不触发。

确认影响剧情的漏镜会计入，即使它可由其他镜头推导、或省图依据还没确定。“能省参考图”不代表原视频已经演出了该剧情。纯表演细节、允许的外观偏差和证据不足不计；看不清先补查，修改分组本身不触发。达到条件且提示词准备完整时，导出对应来源视频的新提示词；默认不生成视频。

提示词沿用输入视频的画幅，按全部脚本镜头每镜 1 秒编排，不删漏镜或可推导镜头，不改变报告中的脚本计划时长。文本只描述脚本已有的画面动作，要求无台词、无声音、无字幕、按镜序硬切。如果关键剧情只能靠对白表达、无法改成已有画面，就会说明冲突，不擅自编造剧情。

提供了原提示词时，会参考其中与脚本相符的画面细节；冲突或重复的内容不会照搬。原提示词不会改变视频审查结论，也不能覆盖脚本、镜头顺序和无声无字幕要求。

交付提示词前，还会核对人物和道具、动作顺序、前后衔接，以及关键动作能否在每镜 1 秒内看清。遇到无法解决的冲突会说明原因，不能靠删剧情或改成完成后的静止画面来凑时长。

每个确认失败或漏镜都必须写清楚：脚本中哪句话证明有问题、问题会造成什么影响、准备怎么改。依据不完整时停在报告阶段，说明缺项。导出文本不需要 API 密钥，不占生成额度；旧付费任务和预算限制会保留。

你生成新视频时需要按提示词对应顺序提供**原资产图**，并设置注明的时长、画幅；原视频用来审查，不默认作为视频转视频素材。生成后把新视频交回来，Skill 会重新检查，不能仅凭提示词就保证新视频没有瑕疵。

如果处理中断，可以从已完成的步骤继续。已经交付的结果需要补正时，会在新目录生成修订版，并保留旧结果。

## 你可以这样对它说

```text
请检查这个 AI 预演视频。
视频：D:\\project\\previs.mp4
脚本：D:\\project\\script.md
资产图：D:\\project\\assets\\
Shot 分组（可选）：A01：S01–S03；A02：S04–S06

完成原视频审查，输出 Markdown 和小分镜图。
达到返修条件时，另给我新视频提示词、资产顺序、时长和画幅，由我自行生成。
```

如果本次只需要报告，可以这样说：

```text
本次只审查并输出报告，不需要新视频提示词。
```

## 需要知道的限制

- 找到一张相似的帧，不代表整个镜头已经通过。
- 抽帧看不清的动作或转场，会写明证据缺口和补查方向，不会假装已经确认。
- 某段剧情如果不足 4 秒，且无法在不跨剧情边界的情况下合并，报告会说明分组未完成，需要补充内容或调整计划时长。
- 普通的脸型、颜色或材质差异不会单独判失败，除非影响剧情或连续性。
- 你给的分组如果漏了镜头、重复、顺序不对，或跨剧情段、时长和镜头数超限，报告会说明问题，不会私自改组。画面仍会检查；有问题的分组暂不建议省图，分组问题本身不会触发新视频提示词。分组改动后，省图建议也会重新判断。
- 没有现成视频时，可以整理脚本和资产，但不能凭空证明视频内容正确。
- 字幕、台词、口型和声音是否正确，默认不做完整校对。

## 开发者检查

在仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File tests/run_checks.ps1
```

这会检查 Skill 结构、脚本接口、审查规则和交付流程。
