# AI 分镜图校对 Skill

你提供已经按顺序、与脚本配对好的分镜图，Skill 检查每张图是否符合对应脚本，并适合作为生成参考，再完成原有分组、省图判断和报告。达到返修条件时，另给你整批新视频提示词，由你自行生成。

## 输入

1. 每个脚本镜号对应一张分镜图，按你给的顺序使用，支持 PNG、JPEG、WebP。
2. 完整分镜脚本，保留镜号、画面内容、动作、结果和计划时长。
3. 角色、场景和道具原资产图。

可选提供已确定的 Shot 分组，例如 A01：S01–S03；A02：S04–S06，以及原生成提示词（文本或 TXT/MD）。工具维护图片对应关系和文件指纹，你不用登记或填写 JSON。

原生成提示词只在达到返修阈值后读取和分析。未达阈值时直接跳过这部分工作。

## 怎样判断

检查人物、场景、关键道具、构图、可见状态和相邻图片的连续性，允许不影响剧情的合理视觉差异。

Skill 会按镜头顺序把每 9 张图排成一页，逐镜核对画面内容、前后衔接和能否用作参考。每张图在本次审查中看一次，分页不改变原有分组。

完整镜头动作和参考图所处阶段分开检查。例如脚本是“女孩递出钥匙，男孩接住”，动作前参考图中钥匙仍在女孩手上可以合理；图中已经明确出现错误人物或与该阶段矛盾的持物状态，则指出问题。单图无法证明整个运动过程，不因此自动判错或记待核查。动作关系足够识别时，允许局部模糊、遮挡和道具细节不清；例如敲锣关系可辨，木槌局部模糊仍可通过，不要求精确接触点清楚。

允许景别、拍摄角度、合理动作阶段和非关键细节有差异。比如角色确实做出了举奖杯的动作，奖杯只因构图被裁到画面外，可以通过；画面明确显示拿错道具或站错位置，则不能通过。若构图整体排除了本镜核心表演，也应不通过：例如脚本要求展扇和得意、神秘的眼神，图片却只有背影，脸、手和扇都不可见，属于构图错误，不能靠“之后可能转身”放行。脚本明确要求的角色朝向另行核对，不把背拍机位自动认定为人物转向错误。

看完后逐镜记录结论。有错误时说明对应脚本、画面哪里不符，以及建议怎么修改。只有排除可接受差异和明确错误后，必要关系或参考阶段仍确实无法判断，才标为待核查；说明疑点后直接交付，不放大复看，也不计返修阈值。省图需要明确的前后依据，没有依据就保留原图。

有指定分组就采用，没有才自动分组。沿用同一 Beat 内相邻镜头、每组计划总时长 4–15 秒、最多 12 镜的规则。分组冲突记在内部记录，画面校对继续，受影响的省图暂不批准。

## 输出

- `01_分镜图审查.md`：一张九列表，依次为分组、原镜号、镜头时长、脚本描述、小分镜图、检验结果、图片处理、推导依据镜号、问题或修改建议。
- `images/`：全部输入原图和展示用缩略图。建议省图和待核查的图片也会显示、链接和保存。
- 达到阈值后优先补齐必要信息，在交付文件夹内导出 `G01_新视频提示词.md`，可以直接复制使用。

可以把新建的文件夹或已有的空文件夹指定为交付目录。这个文件夹只放报告、图片和触发后的新提示词；用于中断续接的内部文件单独保存，已有交付不会被覆盖。

通过镜头的问题栏只写“符合脚本”，不再附问题或修改建议。报告时长采用脚本计划时长。省图只建议减少生成参考图，依据在专列说明，所有脚本镜头仍保留。待核查项显示“—”，暂不省图，并说明具体需确认的信息。新报告不包含漏镜条目或补帧建议。

报告和图片由程序自动核对：检查内容是否与已完成的审查一致、每镜原图和缩略图是否对应。校验通过就直接交付，省去最后再人工逐镜核对；有校验错误或刚修改规则时才检查对应部分。逐镜核对在编号总览上一次完成。

## 什么时候输出新视频提示词

满足任一条件就触发：

- 一处有明确证据的关键剧情错误。
- 一处严重画面损坏，妨碍辨认脚本必需内容。
- 普通明确错误涉及至少两镜，且占整批镜头至少 20%。同镜多问题只计一次；2/10 触发，2/11 不触发。

待核查、允许的视觉差异和输入问题不计入错误数。分组、省图和待核查均不改变整批镜头这个分母。未触发不代表所有图片均通过，已有问题仍会留在报告中。

新提示词覆盖整批脚本，每镜固定 1 秒，要求静音、无台词、无说话口型、无新增屏幕文字、按镜序硬切，保留原资产对应、已有可见动作、表情、人物与道具关系及资产风格。对白文字和含义不参与提示词保真或时长检查，不要求把对白独有信息转换成画面，也不为此新增剧情或阻止导出。报告中的计划时长不受影响。画幅自动采用整批分镜图中数量最多的显示画幅，数量并列时采用原镜序中最先出现者，不再询问确认，不裁图；同一比例的不同分辨率合并计数。用户另有明确指定时采用指定目标。

达阈值后，原提示词只参考与脚本相容的视觉细节，不能改变审查结论。新提示词交付前会核对全部镜头的剧情、人物与道具、动作阶段、空间衔接、可见性、资产和一秒内的可执行性。缺少资料时会一次列清；要求冲突也会明确说明，不能靠编造剧情或删除动作凑时长。Skill 到提示词交付停止，不调用 API 付费生成。

提示词会直接放在同一个交付文件夹里，不用再手动搬文件。已有报告和图片会保留，不会被提示词导出覆盖。

## 你可以这样说

```text
请校对这些已和脚本配对的分镜图，按我给的顺序使用。
图片：D:\project\storyboards\（已按脚本顺序排好）
脚本：D:\project\script.md
原资产：D:\project\assets\
Shot 分组（可选）：A01：S01–S03；A02：S04–S06
原生成提示词（可选）：D:\project\prompt.txt

输出分镜图审查报告和全部图片；达到阈值时给我整批新视频提示词，由我自行生成。
```

若本次只需报告，说明“本次只审查，不需要新视频提示词”即可。图片、脚本或原资产替换后会重新核验相关结论；修订另存新目录，旧交付继续冻结保存。

中途停下后，可以从已保存的审查进度继续。继续前会检查图片、脚本和资产有没有变化；如有变化，需要重新核对受影响的结论。

## 开发检查

日常使用只需按上面的示例提供图片、脚本和资产。开发者可查看[技能说明](ai-storyboard-previs/SKILL.md)和[图片批量入口](ai-storyboard-previs/references/storyboard-images.md)；运行环境需要 Python 和 Pillow。

```powershell
# 当前图片流程、提示词与 Skill 校验：
powershell -ExecutionPolicy Bypass -File tests/run_checks.ps1
```

测试使用真实图片文件和模拟审查结论，验证绑定、阈值、画幅、规划、提示词及冻结交付；它们不代表模型已经完成真实图片的视觉验收。
