# AI 分镜校对 Skill

`ai-storyboard-previs` 用来检查一段已有的 AI 预演视频，看看它是否符合你的分镜脚本。

它会把视频画面和角色、场景、道具图对照起来，找出错镜、漏镜、动作不对和前后衔接问题，再整理成容易阅读的 Markdown 报告和小分镜图。

最终默认只交付 **图片和 Markdown**，不交付视频。

## 你需要准备什么

准备以下三类文件：

1. **预演视频**：需要检查的 AI 视频或样片。
2. **分镜脚本**：按顺序写好镜头编号、画面、动作、动作结果和时长（如果有）。
3. **资产图**：角色、场景、道具等参考图，并写清楚每张图是什么。

不需要自己填写项目 JSON。Skill 会自己整理工作过程中的信息。

## 它会怎么工作

1. 先检查文件是否能正常读取。
2. 给视频抽帧，把画面和脚本镜头对应起来。
3. 检查三个层面：
   - **单镜头**：人物、场景、道具、动作和结果对不对。
   - **前后衔接**：人物身份、衣服、位置、手里拿的东西和动作状态是否连得上。
   - **整段故事**：有没有漏镜、乱序或多出剧情，静音观看能不能看懂主要事件。
4. 判断哪些画面应该保留，哪些画面可以建议 AI 补足，哪些镜头确实缺失，哪些还需要人工确认。
5. 只合并相邻镜头，保留原来的镜号、顺序和剧情。
6. 输出报告和小分镜图。

## 你会得到什么

通常会得到：

```text
01_原视频审查.md
images/
  S01-...png
  thumb-S01-...png
```

Markdown 里有两张表：

- **分组结果**：哪些相邻镜头放在同一组、总时长和分组理由。
- **逐镜检查**：镜号、脚本描述、小分镜图、检查结果、图片处理方式和修改建议。

所有原镜头都会保留。即使某一镜没有找到画面，也会在原位置标出来，不会悄悄删掉。

如果你明确授权使用 RunningHub 付费返修，并且问题达到返修条件，Skill 最多自动返修一次。返修后会另外生成 `02_返修视频审查.md`，不会覆盖第一份报告。视频本身仍不会作为默认交付物。

## 返修什么时候会发生

默认只检查和报告，不会自动花钱。

- 没有“必要漏镜”时：至少有 3 个镜头出错，并且出错镜头占本组 20% 以上，才建议返修。
- 有“必要漏镜”时：关键错误或必要漏镜可以直接触发；普通问题仍需至少 2 个镜头且占 20% 以上。
- “待检查”和“可以推导”的镜头不会被当成确定错误。
- 任务超时会继续查询原任务，不会直接重复提交。

## 在 Codex 中使用

把仓库中的 `ai-storyboard-previs` 文件夹放到个人技能目录：

```text
Windows: %USERPROFILE%\.codex\skills\ai-storyboard-previs
macOS/Linux: ~/.codex/skills/ai-storyboard-previs
```

然后直接这样描述任务：

```text
使用 $ai-storyboard-previs，读取这个预演视频、分镜脚本和资产图。
请检查每个镜头、前后连续性和是否漏镜，按原镜头顺序整理分组，
只输出小分镜图片和容易看懂的 Markdown。
```

## 需要知道的限制

- **找到候选帧不等于通过**，还要看画面内容是否真的符合脚本。
- 证据不清楚时会写“待检查”，不会把猜测当成结论。
- 稀疏抽帧不能证明镜头一定缺失；确认漏镜前会继续补查视频。
- 普通的脸部、服装、站位或景别差异，只要不影响剧情，通常不会单独判错；脚本明确要求的关键动作和结果仍必须满足。
- 只提供脚本和资产图、没有已有视频时，无法完成“视频是否正确”的校对；这时只能先整理脚本，真正生成图片或视频需要另外授权和工具。
- 默认不逐字核对字幕、对白文本或口型同步，重点检查剧情、动作和连续性。
