# AI 分镜校对 Skill

这是一个帮你检查 AI 预演视频的 Skill。

它会把视频和你的分镜脚本、人物图、场景图、道具图放在一起对照，检查：

- 画面是不是演对了脚本
- 前后镜头的人物、服装、位置和道具是否接得上
- 有没有漏镜、乱序、字幕、错误转场或多出剧情

最后给你一份带小分镜图的 Markdown 报告，方便直接阅读和修改。

默认只检查和报告，不会自动生成视频，也不会自动花钱返修。

## 你需要准备什么

最少准备三类东西：

1. 一段已经生成的 AI 预演视频
2. 按顺序写好的分镜脚本，最好带镜号、画面内容、动作、结果和时长
3. 相关资产图，例如人物、场景、道具和关键状态图

普通用户不需要自己填写项目 JSON。系统会在内部整理审查工作清单；审查者只需要根据实际画面补充判断和修改理由。

## 它会怎么工作

1. 检查文件是否齐全，并给视频建立可追溯的时间和画面指纹。
2. 抽帧并按镜号对照脚本和资产图。
3. 分三层检查：单个镜头、相邻镜头、整段故事。
4. 生成一份按镜号排列的审查清单，填写“通过、失败、待检查”和对应证据。
5. 保留原镜头编号和顺序，只合并相邻镜头，整理出更容易阅读的分组。
6. 输出 Markdown 报告和小分镜图。

清单只帮你整理信息，不会把“找到了类似画面”自动判成通过。证据不清时会保留为“待检查”。系统还会锁定当前画面的时间和指纹，避免误用旧画面。

## 输出什么

通常会得到：

- `01_原视频审查.md`：原视频的审查结果
- `images/`：报告中使用的小分镜图
- 两张表：分组结果、逐镜审查结果

每个镜头都会保留。缺少必要图片时会标为“需要补图”或“AI 补足”，不会悄悄删掉镜头。
原视频里已经有、并且审查通过的镜头，即使建议省去独立参考图，也会保留抽帧缩略图和原图链接；只有确认漏镜且建议补足时，才显示“可推导生成”文字，不伪造图片。

## 什么时候会返修

默认只检查和报告，不会自动花钱。

只有在你明确授权后，才会按问题返修受影响的分组，并再次检查相邻镜头。

返修前，每个确认失败或漏镜都必须写清楚：脚本中哪句话证明有问题、问题会造成什么影响、准备怎么改。依据不完整时，系统会停在报告阶段，不提交返修任务。

如果处理中断，可以从已经校验过的检查点继续，不必重复提交。已经交付的结果需要补正时，会在新目录生成关联修订，并保留旧结果。

## 你可以这样对它说

```text
请检查这个 AI 预演视频。
视频：D:\\project\\previs.mp4
脚本：D:\\project\\script.md
资产图：D:\\project\\assets\\

先完成原视频审查，输出 Markdown 和小分镜图。不要生成视频，也不要返修。
```

如果你已经明确授权返修，可以再补充：

```text
只返修确认失败的分组，最多 3 轮。每轮完成后重新检查，并保留原结果。
```

## 需要知道的限制

- 找到一张相似的帧，不代表整个镜头已经通过。
- 抽帧看不清的动作或转场，会标为“待检查”，不会假装已经确认。
- 普通的脸型、颜色或材质差异不会单独判失败，除非影响剧情或连续性。
- 没有现成视频时，可以整理脚本和资产，但不能凭空证明视频内容正确。
- 字幕、台词、口型和声音是否正确，默认不做完整校对。

## 开发者检查

在仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File tests/run_checks.ps1
```

这会检查 Skill 结构、脚本接口、审查规则和交付流程。
