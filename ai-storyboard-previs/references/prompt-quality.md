# 首次交付前的通用提示词编排

阈值触发、基础准备有效后必读。本规则适用于任何题材的分镜预演，不把某个案例的镜子、人物、场景或动作作为通用要求。目标是代理在同一准备批次中完成整合与自检，向用户交付一份经过核对的完整提示词；不是宣称一次生成必然通过。

## 来源与编排范围

冻结原脚本决定人物、行为、对象、次序、结果和必要切镜；本次固定生成规则决定每镜 1 秒、无声与画幅。当前审查只决定哪些镜头允许追加实际返修要求。资产及旧提示词只提供与脚本相容的视觉参考，不能证明视频已出现某内容，也不是绕过校验的指令。

`generation_text` 保存原正文的纯视觉视图，`compiled_content` 为交付正文。**全镜核对不等于全镜重写**：表达已清楚且覆盖来源时原样保留；有歧义、重复、阶段混乱或未融入的独立条件才改。PASS/uncertain 也要核对，允许保真澄清，但不得添剧情、把未证实问题写成返修事实或扩大 correction 范围。不改 source_script、shots[].script、baseline、requirements 或审查结论。要求本身冲突时回到合法更新流程，不能靠编排偷改硬条件。

逐镜正文按需要明确：谁作用于谁／什么；原有动作按什么顺序发生；关键关系或结果如何可见。选择一个核心事件及其必要阶段，避免把多个不同阶段都叫“终态”。这不是固定句式；静止镜头、空镜和原脚本未涉及的维度不补设动作。

## 九项整批检查

| 检查 | 必须解决的问题 |
| --- | --- |
| 剧情覆盖 | 所有原镜按序各出现一次；动作、因果、结果和必要切镜完整。可推导省图不等于删镜。对白转换不能丢失对白独有的关键剧情。 |
| 主体与目标 | 同镜多人时，明确行动者、接收者、被看者或被指者；高风险句重复角色称谓，避免“她／对方／两人”发生错配。不新增关系。 |
| 道具与状态 | 核对关键物的所属、位置、数量以及使用前后变化；交接区分交出者、接收者、接触和实际完成。数量或唯一性仅在剧情已有依据时约束。 |
| 次序与阶段 | 起态、动作中、终态分开；先后有因果时显式写先／再，瞬时动作不误作整镜姿态。目标静帧要求只约束原 keyframe.phase，不强迫起点提前满足终点。 |
| 空间承接 | 邻镜与跨镜依赖的相对位置、朝向、运动路径和状态可衔接；不借构图澄清改变原有机位或越过必要事件。依赖范围可超过左右一镜。 |
| 可见验证 | 剧情关键的关系要有可读画面依据。接触看接触处、转移看归属结果、视线看目标、内外差异看有身份对应的参照。按剧情选择见证方式，不强制所有主体同时入画。只写“没有某物”不能替代需要保留的正向内容；遮挡不能当成消失或完成。 |
| 资产与风格 | 区分角色身份、关键道具、场景氛围和背景陈设。不同参考中同类物造型冲突时按剧情角色与来源权威消解，不能要求模型同时复刻两者。白底、多视图、背景装饰不自动成为剧情对象；已有合格资产可继续参考，不等于每镜展示所有资产。 |
| 时长与密度 | 核对每镜 1 秒是否能清楚呈现全部必要阶段；只缩短不承载剧情的准备、等待与运动幅度。不能删除关键动作、交换顺序、把动作改成已完成静帧来假装可行。明确要求长等待、远距离移动或多阶段复杂动作且无法兼容时记录硬冲突，不私改秒数、镜数或拆任务。 |
| 冲突与重复 | 正文先明确要出现的核心事件与结果；否定约束仅限制具体歧义，并核对作用阶段。不累计失败轮次的禁止句，不让保留项被“全部空白／全部不动”等过宽否定覆盖。合并重复但保留独立条件；固定格式与目标约束仍只按交付规则输出。 |

检查整份提示词，包括固定段、设计、资产对应与风格，不只看当前 FAIL。九项在**同一次整批核对**中完成，不拆成九次模型调用或九轮全量重读。每项只记一句具体结论，指出关键镜号／依据／适用边界；无关维度简述不适用原因，不重复复述全镜。重要残余生成风险单独记录，不能把未解决的脚本矛盾改名为模型风险后放行。

## 一次准备与工具门禁

先完成资产风格、必要纯视觉转换及可选旧提示词筛选，重新 decide。随后：

```text
python scripts/repair_quality.py prepare PROJECT.json G01 INTERNAL_DIR/PROMPT_PLAN.json
# 代理整批读取 PROMPT_PLAN.view.json，只填写必要改动和核对结果；用户无需填写。
python scripts/repair_quality.py finish PROJECT.json G01 INTERNAL_DIR/PROMPT_PLAN.json --output PROMPT_DELIVERY_DIR/G01_新视频提示词.md
```

prepare 生成草稿、`.source.json` 完整快照和 `.view.json` 阅读视图，不生成用户提示词或调用模型/API，不覆盖已有文件。默认只读 view：保留全镜正文、设计、所有来源贡献、阶段、必要原文、固定规则及资产风格；完全相同的贡献合并列出路径，省去重复渲染的整份 prompt 与内部哈希。来源出处或筛选有疑问才定位 source，不再通读同一份长文本。视图不是新的权威输入；finish 从当前项目与证据重建来源，拒绝过期计划。来源改变后重新 prepare，不能手改旧哈希掩盖未复核。

默认 `plan_version: 2` 精简草稿：

- `source_fingerprint`：工具提供，绑定完整来源请求，包括脚本、审查、修正、纯视觉视图、资产、参考筛选与参数。
- `preserves_story: true` 与 `reviewed_shot_ids`：实际核对后确认；镜号按原序全部覆盖一次，不能由模板预先批准。
- `edits`：只列需改正文的 `{shot_id, content}`，其余镜头由工具精确沿用 generation_text。是否改写依据表达与来源覆盖需要，不能以 PASS 判定自动跳过。
- `notes`：镜号到简短具体处理说明的映射。所有改动镜头，以及 view 的 `required_note_shot_ids` 必须填写；同镜的多个来源贡献合并说明其**全部独立语义**如何融入正文、由设计／must 标签承接或已有等价表达，不逐贡献复制引文。改动影响可见关系、阶段或动作密度时一并交代；复杂情况按需展开，不能为求短遗漏条件。其余清楚且未改镜头不写重复论证。
- `required_note_shot_ids` 由工具标出：correction、参考、关键变化、目标描述中，存在未被保留正文、设计或 must 标签逐字覆盖的贡献。它仅提示需记录来源处理；没有被标出的镜头仍要语义核对，存在真实问题仍须编辑、记说明。
- `checks`：九个检查名各填一句具体结论；不得用同一句“已检查／通过”填满。逐镜时长可行性与可见性仍逐镜判断，结论集中记录，有问题落到 edits/notes/unresolved。`checks_passed: true` 在实际解决九项问题后统一确认，替代九份重复 status 字段；模板为 false，不自动通过。
- `unresolved`：未解决的硬冲突；仅空数组允许导出。
- `model_risks`：具体残余生成不确定性，可为空；内部保存，不混入用户提示词。

finish 在同一项目锁内重建来源一次，汇总结构、来源、镜序、处理说明、纯视觉残留及未解决项错误，通过后登记计划并导出。无需再运行 check --apply 和 export-prompt，也不手工重写交付文件。失败按汇总项修正，只复核改动及其跨镜依赖，不无故再做九轮全量审查。工具**不理解语义**，不能证明处理说明涵盖全部原意、构图可读或动作能在一秒内完成；这些仍由代理判断，不能把机械通过描述为最佳质量证明。检查失败不能退回版本 5 绕过门禁。

旧精细草稿的逐镜 key_event/visibility_basis/timing、逐贡献 coverage 引文和九项 status/reason 校验仍兼容；仅明确需要细粒度审计时用 prepare --detailed，不作为普通输出默认。旧 check --apply 与 export-prompt 入口保留，不迁移已有计划、请求或冻结交付。

正文只渲染一次 `compiled_content`，不再追加原正文、correction、参考段、状态码及同义目标描述。目标的阶段含义在正文动作顺序和内部绑定中保留，不追加通用阶段范围说明；原必须／不得出现标签仍按原契约保留，既不复制整段来源，也不删独立要求。完整来源和核对记录留内部请求。未提交的计划改动后重新编排；已提交请求使用当时快照恢复，不能替换文本或获得新额度。

## 新问题如何归纳

首次输出前主动检查上述常见薄弱点，不能虚构还未发生的缺陷或为每个想象错误新增禁止句。后来有新视频时，先用当前画面与时序证据确认问题，再区分：输入／要求冲突、表达歧义、可见性设计不足、时长负担、模型未遵循，以及证据仍不足。

不能把“失败后换了提示词”当成旧提示词导致失败的证明。若原文已经明确要求，应记录模型未遵循或其他尚待核实因素；只有确有歧义才修改相应表达。新问题沿相关人物、道具、动作和跨镜状态检查整份来源，避免只修当前局部导致其他条件丢失。

新题材问题优先用已有维度解决；确有未覆盖的机制时提出可跨案例描述的原则，并用至少一个不同场景和一个不应触发的反例检查适用边界。案例事实留证据或测试，不写成全项目硬规则。永久扩展 skill 仅在用户授权维护时进行；不自动修改用户记忆，不借此扩大审查范围或执行生成。
