# 减少重复整理和往返

新任务读取 SKILL 后，直接 overview：只提取原文、时长和已确定的图片对应，生成每9张一页的3×3编号拼图，立即批量显示。不为出拼图先打开其他规则或源码。input_draft 留下机械提取结果，不再重复 extract；首看后按入口内的普通字段约定填写，不另查接口或模板。省图／显式状态建模及特殊证据才查相关规则。

2026-10-14 case1.3 实际任务的用户计时为362.80秒，工具约18.5秒。目录排错、补重复事实、修正收尾状态冲突三阶段合计134.01秒，是该次运行的可避免排错开销，不是保证未来节省的秒数。现统一接受空交付目录、普通保留图输入不强制 facts、prepare 独立预检跨镜状态并集中诊断目录／字段问题。完整脚本段落不能充当 static 状态；没有省图状态依据时保留原图。修复减少失败和重复整理，不自动替代理实际视觉判断。

同日使用该任务的14张原图和已保存的逐镜判断，在独立临时目录验证新入口：复用全部首看拼图及观察，prepare 1.000秒、complete 3.590秒，合计4.590秒；一次成功，保留12镜通过、1镜不通过、1镜待核查，1处普通错误未触发提示词，原历史文件指纹不变。这仅测准备与交付的程序执行，不含重新看图、代理填写字段、工具调度或首看拼图生成，不能与362.80秒的端到端任务直接比较。

随后两次批量工具操作：prepare --reuse-overviews 核验复用首看拼图，生成全批证据上下文、精简阅读视图、当前要求／相关原资产审查包与空工作单；代理完成实际校对后，complete 同一锁内登记、规划、判阈值、渲染、自动校验和冻结。不逐镜调用工具，不重复 context、规划、预检或渲染。

新策略每张分镜只看一次，首看观察落盘并自动带入正式工作单。批量显示未看页，不显示或生成资产拼图，不放大疑点，不重新打开前页末镜；清楚矛盾直接 FAIL，必要细节不清直接 uncertain 后交付。跨页使用已有相邻可见事实，三组检查和三级放宽同次判断。恢复只处理未记录/不完整字段，不把待核查排成复查任务。

2026-10-14 独立 overview 入口实测：14张1920×1080噪声 PNG、共73.35MB，三次新启动 Python 到两页首看拼图及机械草稿全部落盘为2.025／1.816／1.892秒，中位数1.892秒。包括进程启动、解析、来源核验、图片解码和拼图写入；不含测试图片生成、代理阅读／思考、工具调度、显示或视觉判断，也不表示操作系统文件缓存未命中。可用开发仓库 tests/benchmark_initial_overviews.py 重测。独立入口、校验复用及旧流程兼容检查加入后全套131项通过，测试中的审查判断为模拟值。

旧策略对照记录（不是新流程要求）：2026-10-14 本地模拟准备测试：14张1920×1080图片、4张1440×900原资产，三次中位数为仅分镜总览0.881秒、含逐页包及资产总览1.084秒，新增约0.203秒；仍为两页分镜总览，4张资产共享1张资产总览。这里只测本地材料生成，没有测模型视觉判断、实际错误复核或端到端耗时，不代表已验证提速比例。跨页、资产来源、局部待核查及兼容测试加入后全套123项通过，视觉判定使用模拟值。

## 准备与阅读

一次保存完整原脚本、逐镜原文、资产和时长来源。精简 INPUT 省去固定字段与空数组；purpose 与 required_result 相同就复用，阶段与关键状态仍单独判断。共同 requirements_template 按明确 scope 写一次，各镜显式引用，不跨时空套用。只写状态种子和实际变化，由程序计算完整状态。

按阶段读取：普通任务只需 SKILL 和原始输入，按入口内字段约定补齐并交付；显式状态建模、省图或特殊证据才查独立字段速查，来源／阶段等不明才查镜头要求对应段落；需要自动分组才查规划；阈值触发才查提示词规则、分析原提示词及填写资产风格。已读且未变的规则复用，不提前读无关资料。首看事实不自动构成 PASS；根据当前脚本与明确要求记录结论，复用已有观察，不再次开图。

visible_facts 一次记录，须足以支持身份、阶段与三组检查。PASS 不扩写问题与建议，由程序写“符合脚本”；FAIL／uncertain 保留具体原因，省图保留双侧依据。工具复用的是事实和机械字段，不是自动批准。

## 缓存与交付

一次操作内缓存图片信息、哈希及上下文，结束前重验全部依赖内容。输入改变就失效；不能用缓存结论批准新图片。总览可辨认的逐镜项目直接完成，必要细节不清直接待核查，不猜关键关系；减少的是开图次数，逐镜结论与依据照常记录。

交付格式 3 自动核对表格全部九列、原图对应／哈希／链接、缩略图预览、镜序及文件集合。成功直接交付，省去第二次人工整表与图片核对；失败或刚修改渲染／规则才定位检查。初次实际看图仍完整进行，旧交付冻结、修订另存。

## 触发后的提示词

原提示词 prepare 只记路径，达到阈值才打开、登记并筛选。未达阈值不做这部分准备。缺项只影响提示词，审查报告照常完成。

缺项一次汇总在 FINISH_REPORT 和 PROMPT.inputs.json，不逐个补齐再重跑。内部清单给出全部原资产与 SHA、需纯视觉转换字段的原文与 SHA、旧提示词来源和画幅，代理按需看原资产并同批填写对应项目字段，不为查这些值通读脚本代码或重读整份项目。补齐后直接 repair_quality prepare，由工具核验仅风格造成的绑定变化；不单独 decide、不重做 complete。证据、脚本或审查真的改变时仍先重新核验。

complete 已输出 PROMPT.view.json／PROMPT.json 就直接阅读填写，不再 prepare。全镜来源视图合并重复贡献，plan_version=2 仅写必要 edits、来源处理 notes 和九项具体结论。全镜核对一次完成，清楚且已覆盖的原正文保留，不拆九轮重读或逐镜调用。finish 重建来源一次、集中汇总错误后导出。

提示词 source_request、prepare 和 finish 复用各自的一次证据周期，避免内部审查／聚合／画幅核验反复打开图片和读取同一文件；每次结束仍对全部依赖重新计算 SHA，再保存计划或导出。缓存不跨操作保留，不按文件大小或修改时间认定未变。

## 计时口径与阶段预算

收到任务即记录 t0，随后读取入口及来源；首看拼图产出记 t_overview，实际显示记 t_first_view；输入补齐记 t1，prepare 完成记 t2，实际看图并填完 WORKLIST 记 t3，complete 冻结交付记 t4。单独报告 t0→t_overview 和 t0→t_first_view，才能定位“读 Skill 到拼图”的耗时；它们是 t0→t1 的子区间，不重复计入总时长。触发提示词时另记开始／结束。使用实际 UTC 时间或同一单调时钟，不用文件修改时间推算代理耗时。

| 阶段 | 计时范围 | 约14镜、两页总览、已有分组的目标预算 |
| --- | --- | ---: |
| 规则与输入 | t0→t1，含首次阅读、提取、字段整理、工具调度 | 40秒 |
| 准备 | t1→t2，含 prepare 与总览生成 | 5秒 |
| 视觉判断与记录 | t2→t3，复用首看事实，补齐全部逐镜判断及工作单，不放大复看 | 125秒 |
| 收尾 | t3→t4，含 complete、自动校验与冻结 | 5秒 |
| 余量 | 上述阶段外的必要调度 | 5秒 |

180秒是优化目标，不是质量截止线或已验证保证；复杂细节、异常输入、无原分组或触发提示词需如实延长。表内每秒只计一次，已包含的调度不得重复加入余量。不能为了赶时限减少逐镜检查、猜测不可辨认细节、复用旧结论或改变 FAIL／uncertain。

内部 TIMING.json 记录每阶段真实起止、总墙钟、程序耗时、重试及可核实等待。总墙钟 t4−t0 包含阅读、思考、调度和失败重跑；程序耗时只是其中一部分，不能冒充全流程。补测起点晚于首次读取时明确遗漏范围，不补造 t0；无打点就写未记录。最终回复若不计入须说明。剔除上下文压缩时只扣有记录且与区间重叠的部分，同时报告原始间隔、剔除值与净耗时；用户等待另列，不悄悄扣除。

## 提速优先级与实测边界

1. 先消除可避免的报错。直接填写生成的版本4工作单，对照字段速查，FAIL 只写 findings 一次，由 complete 展开 reason、issues 和返修依据；不另读完整返修格式或写重复全批检查。原图沿用路径与扩展名。规则／字段有冲突时定位该处，不能反复通读整套代码。脚本自身异常要修复原因，不能删除事实或关闭校验求通过。
2. 再减少读取和撰写。首次直接 overview 出图，不把字段整理放在拼图之前；当前会话已读且未改的规则不再读。公共约束只写一次，事实和必要判断集中填写，PASS 不扩写。存在当前工作单并不代表已实际审查。
3. 保留必要视觉工作。两页3×3总览可以替代14次开图，手部、持物或空间细节不清就待核查；连续性和全部七项检查仍逐镜完成。渐隐、渐白等过程帧按当前阶段判断，不因尚有前态残留而自动失败。
4. 收尾只跑一次正常 complete。修正实际错误后才重试；自动交付校验通过后不重复人工整表核对。未达阈值不读原提示词或进入提示词准备。

每个结论只写一次：PASS 仅结论、阶段、放宽级别及已有可见事实；FAIL 在 findings 中一次写完同镜引文、实际矛盾、修正及种类；uncertain 在 unresolved 写一次疑点。省图的双侧依据仍单独明确填写，关键错误及严重损坏仍需明确剧情影响。展开只复用字段，不猜测判断；来源指纹、最终完整核验、阈值与旧工作单兼容保持不变。内部数据放在交付同级 `.storyboard-internal/本次任务/`，不在 case 交付内反复创建或搬运内部目录。

2026-10-14 的14镜熟悉案例中，重新整理输入的执行区间为193.07秒：规则／输入61.06秒、prepare 3.11秒、视觉判断与记录125.25秒、complete 3.65秒，另有少量调度差额；本地提取／准备／收尾程序合计6.98秒。该区间未含最初入口读取及最终回复，因此既未达到三分钟，也不是全会话计时。可优先验证把输入阶段从约61秒压到40秒，不能据此声称已经省下21秒。

另一次145.54秒记录复用了已整理输入，且之后还纠正过过程帧判断，不作为同口径、无返工的三分钟达标证据。机械重放旧判断得到的约6.5秒仅衡量程序。后续对比需声明冷启动／会话内复用、是否熟悉案例、哪些材料复用、是否重新实际看图及有无后续纠错；只有同口径结果才能计算提速幅度。外部模型截图所述时长标为自报，不能与本地打点混用或推算精确占比。

## 环境

复用可用 Python 3.10+ 与 Pillow，Windows 使用 PYTHONUTF8=1 并固定解释器路径。缺模块仅补缺项，不在每个项目重复探测、下载或安装运行环境。维护脚本时针对修改分支验证；仅当当前安装实际提供 tests/run_checks.ps1 时才使用该入口，不假定安装包包含开发仓库的测试文件。

## 上下文占用与恢复

SKILL 只路由当前阶段；常规使用不通读源码、PROJECT、完整 CONTEXT、模板和全部 references。优先字段速查、REVIEW.view 和 PROMPT.view；原图及完整证据始终保留。REVIEW.view 只合并重复要求并省略机械哈希，不摘要脚本或状态，{$ref:Rxx} 必须与 shared_requirements 一起理解。默认 CLI 简报省去大型来源／冻结清单，完整结果仍落盘；--detailed 仅供定位需要。

每页看图后保存判断到 WORKLIST，摘要保留 RUN.json 绝对路径、阶段和下一步。压缩后用 resume 检查来源和字段进度，--shots 局部读取自动带相邻镜头；未落盘的判断仍须重核，不能依据聊天摘要直接 PASS。远处省图锚点／组界按需补读，全局连续性、分组、全部镜头及提示词语义检查照常完成。恢复入口不重建输入或覆盖交付，来源变更仍按原失效规则重新核验。

这减少每轮输入和压缩后的重读成本，不保证长会话永不压缩，也不等于实测端到端提速。上下文字符／字节减少量、程序时间与真实模型执行时间分开报告。

2026-10-14 的上下文改造按字符数核验：入口从5989字缩至3431字（约43%）；3镜模拟错误审查的完整收尾结果3177字、默认简报1014字（约68%减少），阅读上下文7674字、精简视图6750字。样例使用真实图片文件与模拟判断，只衡量文本占用；没有测量真实模型的压缩频率、token 数或端到端时间。

## 一次看图优化的计时边界

旧14镜记录的视觉与记录阶段为125.25秒，未单列放大、资产对照和重复记录耗时。节省25–45秒只能作为待验证目标，不能报告为实测；缺少复查的正常批次收益更小。首看、输入整理、正式判断及交付时间各计一次，首看事实复用不产生第二轮看图。用真实任务同模型前后计时验证，不用本地拼图耗时代替。
