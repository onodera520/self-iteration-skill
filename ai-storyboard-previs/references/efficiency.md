# 减少重复读取与执行

## 当前入口与阅读范围

普通新任务按 [技能入口](../SKILL.md)执行 review_storyboards.py start／submit。start 登记原始材料并生成总览，返回 REVIEW.json；立即批量显示未看分镜页，同次逐镜保存事实和判断。不要在看图前手工编写 INPUT、OBSERVATIONS、WORKLIST、完整 requirements 或临时转换脚本。submit 自动展开并调用原 prepare／complete，不再手动重复这条链。

默认只读入口及用户材料。显式状态建模、省图或特殊证据才读 [字段速查](fields.md)；来源／阶段不清才定位 [镜头要求](shot-requirements.md)相应段落；自动分组才查 [规划规则](planning.md)。原 prepare／complete、旧工作单和恢复细节见 [图片接口](storyboard-images.md)，不作为新任务的第二套步骤。已读且未变的规则直接复用，不通读源码、完整 PROJECT、CONTEXT 或全部模板。

## 一次观察，一次记录

三组检查与三级放宽在同一次看图中完成，尺度见 [图片审查规则](storyboard-review.md)。可见事实只记一次；PASS 不扩写，FAIL 只在 findings 写同镜引文、实际不符、修正与种类，uncertain 只在 unresolved 写疑点。省图双侧依据、关键错误及严重损坏的剧情影响仍明确填写。空字段、已有事实或程序成功均不代表 PASS。

每张图本轮只看一次，跨页连续性复用相邻已存事实；不生成或显示资产拼图，不重开前页末镜，不放大或将 uncertain 排成复查任务。动作可读、合理过程帧、局部画外、核心表演缺失和角色朝向的边界统一按审查规则判断，不因提速改变尺度。完整脚本、原图及全部必要判断照常保留。

普通保留图任务不要求重复编写 facts；需要省图／状态建模时才按原约定补真实依据，没有依据就保留图。共同约束按明确 scope 和逐镜引用复用，不跨时空套用。只写新增状态种子与实际变化，由工具计算出口；不能删除事实、改名或关闭校验来消除报错。

## 缓存、收尾与提示词

复用一次操作内的图片信息、哈希与上下文，结束前对全部依赖重算 SHA。缓存不跨操作保留，不按大小或修改时间认定未变；输入改变使相关结论失效，不能用旧判断批准新图。

submit 成功后按返回记录续接，不重复 prepare／complete、规划、预检或渲染；失败只修对应字段或按检查点恢复。冻结前自动核对九列表、逐镜原图及哈希、缩略图、链接、覆盖、顺序与文件集合。校验通过立即交付，不再人工逐镜重看；校验失败或刚修改规则／渲染时才定位受影响部分。内部数据保存在交付同级 .storyboard-internal/本次任务/ 或独立运行目录；接受空交付目录，旧交付冻结、修订另存。

未达阈值不读原生成提示词、不准备提示词。达到阈值，报告冻结后的下一优先事项是导出整批新提示词；报告 complete 不等于提示词已交付。一次读取 FINISH.view 指向的 PROMPT.work.view，复用 submission_template 填 preparation、必要 edits、四组具体结论及适用的原提示词筛选，直接 finish，不再读空 work 或同时读旧 inputs／view。全部镜头和九项检查仍覆盖，不能用空结论、笼统兼容性说明替代实际筛选。

原资产风格来自用户原资产；未看过的原资产原图按需同批显示，不生成资产拼图。来源、哈希、未改正文及绑定由工具维护。新提示词直接写入当前 case 并独立冻结，不先外导再复制。筛选引文与字段报错在同一视图修复，不为缺字段通读源码或重做有效审查；证据、脚本或判断确实改变时仍先重新核验。仅历史任务或特殊诊断按需查 [提示词规则](auto-repair.md)与 [编排规则](prompt-quality.md)。

## 中断恢复与上下文

逐页保存实际判断。新入口摘要保留 SESSION.json 绝对路径、阶段和下一步；提交前读 REVIEW，只继续未完整填写镜头，不重开已看图片。提交后按 prepare/RUN.json 和 resume 续接；已 complete 只读 FINISH.view，below_threshold 直接交付，其余按 prompt_work／prompt_work_view／prompt_output 优先导出。来源变化先核验，未落盘且无法确认的判断保留待核查，不能凭聊天摘要 PASS。

确需旧接口的局部阅读时，--shots 带相邻镜头，远处省图锚点及组界按需补读；全局连续性、分组、全部镜头及提示词语义检查不因局部读取缩小。精简视图只去机械字段和重复要求，不摘要原脚本或状态；{$ref:Rxx} 与 shared_requirements 一起理解。默认 CLI 简报保留恢复路径，完整结果仍落盘，--detailed 仅供定位。

## 环境与计时

复用可用 Python 3.10+ 与 Pillow；Windows 使用 PYTHONUTF8=1 和已验证解释器。只补缺组件，不在每个项目重复探测、下载或安装。保留 Python 缓存。开发检查仅使用实际存在的 tests/run_checks.ps1，不假定个人技能包含开发仓库测试。

起点在首次读技能前记录。首看总览产出与实际显示分别打点，实际观察、字段记录、submit、提示词导出各计一次；使用实际 UTC 或同一单调时钟，不按文件修改时间推算，不重叠累加。结束采用 submit 返回 ended_at、finish 输出 Export completed at (UTC)，不再等下一轮模型调用读钟。旧日志缺完成时间时取工具成功事件并说明口径。

内部 TIMING.json 保留真实起止、总墙钟、程序耗时、重试、失败及可核实等待。总墙钟包含阅读、思考、调度和失败重跑；缺起点如实说明，不补造。最终回复是否计入须说明。剔除压缩只扣有记录且与区间重叠的部分，并同时报告原始间隔、剔除值及净耗时；用户等待另列，不悄悄扣除。

原约14镜、两页总览、已有分组的180秒预算只作优化目标，不是质量截止线或实测保证；复杂任务、输入异常、自动分组及触发提示词如实延长。不能为赶时限减少检查或改变 FAIL／uncertain。对比性能须说明冷启动／会话复用、案例熟悉程度、材料与判断复用、是否重新实际看图及后续纠错。程序回放、文本字符／字节减少、模型端到端耗时分别报告；不能用拼图或旧判断回放耗时冒充视觉审查提速，也不保证长会话不压缩。
