# 视频来源分组与实证聚合

## 默认：用户视频来源组

用户提供视频、脚本和资产图。先按输入视频对应的连续脚本范围登记来源组；不按未来生成模型拆改输入视频，也不运行初始 --apply 规划。最终相邻聚合在抽帧审查后确定。

未指定下游模型时，PROFILE 仅是明确标为假设的聚合约束：max_shots_per_group 不超过工具上限 12，max_images 可设为同一上限，max_fill_per_group 不大于 10；时长范围覆盖本脚本，成本字段设 0，比例采用输入画幅。它不表示模型能力或报价，不需要 API 模型发现。

## 旧生成模式兼容：只划必要试生成组（默认跳过）

默认 video_input_mode: assets。每组按项目 assets 顺序上传用到的全部资产；图片编号表示资产，不等于镜头编号。根据同场景、同连续事件的相邻区间、模型图片数及时间限制分组。组内每镜仍硬切，不能合并叙事事件或减少镜头。

保留用户时长与画幅；未给定时可提出每镜约 1–2 秒，关键交接适当延长，再核对模型准确限制。单镜资产数仍超限则换合适模型或说明阻塞，不静默丢资产，不为规避限制临时生成独立分镜图。离散时长不兼容时调整方案需明确依据，不能暗改原脚本。

直接使用用户提供的视频提示词，保留原文于 user_video_prompt；单组不自动追加旧版基础提示词或 requirements。多组在 groups[].video_prompt 中保存对应片段，只适配资产编号、区间和模型输入，不另设提示词创作步骤。初始分组或返修拆组完成后再填写各组片段；拆组不会继承整段 video_prompt，避免重复提交全故事。不能将全故事提示词重复用于每一组。用户提示词与原脚本的明显冲突在一次输入整理中发现并澄清；审查依据始终是原脚本。缺失关键动作、顺序或必要切镜仍照常判定问题，不因提示词漏写而放宽。

首次多图试生成必须检查真实镜头对应，普通多图能力不保证按脚本切镜。未生成邻组导致边界暂缺不等于本组失败；先记录局部观察，继续独立组生成，边界就绪后补核对。顺序、必要硬切、漏镜、字幕均属于视频审查，不能因仅交付图片而免查。

## 审查后：生成独立聚合与省图建议

组级审查同时输出 reference_assessments，规则规划只读取当前有效结果：

| 审查依据 | 规则处理 |
|---|---|
| 人物首次出场、关键状态/空间变化、叙事转折、不可可靠补足 | 保留 anchor |
| matched 且组审查通过，资产与前后镜头可承接，无需独立约束的关键变化 | ai_fill 候选 |
| 匹配 uncertain/absent、画面错误、证据失效或不足 | pending，不批准省图 |

读取当前选帧并在副本中运行已有相邻区间求解。组首尾、场景边界、关键结果、未知关键事实、用户锁定图仍受硬规则保护；`ΔI≈0` 不能独自批准省图。ai_fill 必须由同组已通过的前后锚点夹住，不跨越 pending 锚点。

先满足模型图片数、时长、比例、镜头数及 max_fill_per_group，随后比较估算视频成本、保留参考图数量、补足数量及分组数，固定规则处理同分。此处只计算建议，不进行提交，也不估算付费补图。初始资产分组的成本比较保持原逻辑。

最终建议可重组相邻镜头，但不覆盖实际生成 groups、版本或时间映射。来源可能涉及多个生成组，通过 source_group_ids 关联；跨原组边界须有有效边界审查。

成功的资产直生视频提供“这些内容曾被生成且可衔接”的证据。它不证明新聚合与参考图组合也可生成。所有 ai_fill 默认标建议/未验证；除非用户另行明确专项模型与预算，不追加付费试验。
