# 视频来源分组与实证聚合

## 默认：用户视频来源组

用户提供视频、脚本和资产图。一份视频登记一个来源组及其应覆盖的连续脚本范围；来源组不是最终聚合，不运行初始 --apply，不调用 API。

已有视频的 PROFILE.json 可写 `{}`。审查后规划按连续事件划分相邻区间，不读取模型时长、离散时长、图片数或成本限制，也不要求脚本时长。为复用现有枚举求解器，每个区间仍最多 12 镜（内部计算上限，不是模型能力）；首尾保留，最多 10 个内部省图位置。超过 12 镜的事件在内部拆分，并在分组理由注明计算上限。

## 连续事件决定边界，场景变化保护参考图

完整脚本的一次整理中填写每镜 event，组级审查同时核对事件划分，不新增逐镜 LLM 判断。按同一行动目标及其连续发展组织事件；新的行动目标、独立事件或明确时空跳跃另起事件。景别变化、特写插入、必要硬切不自动拆组；推门到门外追出可属于同一事件。同场景也可能有多个事件。事件推断须标 inference 并引用脚本，不把叙事解释升级为事实。

例如雨夜追伞八镜：S01–S02 为“林默雨中离开，接身体细节，建立淋雨状态”；S03–S06 为“苏晴从看伞、望人到作出决定，完成犹豫过程”；S07–S08 为“推门、到门外开伞并追出，构成连续行动”。这是该脚本的事件解释，不是固定镜数模板。

有 event 的已有视频项目，区间必须相邻且 event.id、continuity_id 相同，可以跨 scene_id；不改 continuity_id 或状态继承来凑分组。事件先限定区间，再在区间内优化参考图；不同事件不能为省图合并，非相邻的同编号事件也不合并。场景首尾、关键状态及结果继续保留锚点，S07/S08 同组不意味着可以省去推门或开伞结果。组属于脚本事件，不代表画面通过；伞提前撑开等问题仍逐镜列出。

旧项目完全没有 event 时沿用同 scene_id、同 continuity_id 的规则，不猜测事件。新增 event 必须一次覆盖所有镜头；修改后重新绑定来源视频、匹配和审查，不能沿用旧 PASS。CLI 和旧生成模式保持兼容。

## 审查后：生成独立聚合与省图建议

一次组级审查同时输出 shot_reviews 和 reference_assessments。逐镜检验独立，不要求全组 PASS 才保留其他已通过镜头。

| 当前依据 | 规则处理 |
|---|---|
| 人物首次出场、关键状态/空间变化、叙事转折、关键结果、必要锚点 | 保留参考图；若必要内容确认缺失，计入 bad_num |
| matched、该镜 PASS、有已通过前后锚点和资产支持，无关键变化 | 可推导省图候选，仍是未验证建议 |
| 完整补查确认 absent、有已通过前后锚点和资产支持、可可靠推导 | 可推导省图候选；保留“视频漏镜”结论，不能标检验通过 |
| confirmed absent 且无法推导或受必要锚点规则保护 | 必要漏镜，需补生成 |
| matched 但逐镜 FAIL | 该镜需重新生成，不计必要漏镜 |
| uncertain、来源失效、证据不足或推导未定 | 待检查，不批准省图，不计必要漏镜 |

在项目副本中运行相邻区间规划，保留组首尾、场景边界、关键结果、未知关键事实和用户锁定图。`ΔI≈0` 不能独自批准省图。ai_fill 的两个依据镜号必须是同来源组中已检验通过且保留图片的前、后锚点，顺序夹住该镜，并在最终同一聚合组内。不得让缺失镜头或其他 ai_fill 互相作为依据。

先满足事件边界、状态连续性和上述硬约束，再减少保留图片数量；同分按补足数量、分组数和固定顺序取舍。分组理由使用具体事件说明。时间戳只定位原视频画面，不参与区间判定或时长验收。原镜号、顺序、剧情和必要切镜始终保留。跨来源组聚合须有当前有效边界检查，失败或不确定的边界阻止跨越，即使 event.id 相同也不例外。

结果保存为独立 aggregation，不覆盖来源 groups、版本、抽帧时间和任务。省图结论绑定当前脚本、资产、视频、匹配、完整补查、依据图和审查指纹；缺失镜头不伪造对应帧证据。来源变化后相关结论失效。

每份来源视频分别统计 missing_required。默认 bad_num >= 2 且必要漏镜 / 应覆盖镜头数 >= 20% 才建议重新生成该视频。轻微错误、可推导漏镜及待检查不计数。比例按原视频应覆盖的镜数计算，不按最终聚合组计算，也不因省图减少分母。结果仅存内部 missing_summary；交付不增加视频结论表。

输出聚合与省图建议，不保证未来 AI 一定复现该画面。所有 ai_fill 标建议/未验证，不启动专项生成验证。展示规则见 [项目约定](project.md)。

## 旧生成模式兼容：只划必要试生成组（默认跳过）

此兼容模式使用 video_input_mode: assets。每组按项目 assets 顺序上传用到的全部资产；图片编号表示资产，不等于镜头编号。根据同场景、同连续事件的相邻区间、模型图片数及时间限制分组。组内每镜仍硬切，不能合并叙事事件或减少镜头。

保留用户时长与画幅；未给定时可提出每镜约 1–2 秒，关键交接适当延长，再核对模型准确限制。单镜资产数仍超限则换合适模型或说明阻塞，不静默丢资产，不为规避限制临时生成独立分镜图。离散时长不兼容时调整方案需明确依据，不能暗改原脚本。

直接使用用户提供的视频提示词，保留原文于 user_video_prompt；单组不自动追加旧版基础提示词或 requirements。多组在 groups[].video_prompt 中保存对应片段，只适配资产编号、区间和模型输入，不另设提示词创作步骤。初始分组或返修拆组完成后再填写各组片段；拆组不会继承整段 video_prompt，避免重复提交全故事。不能将全故事提示词重复用于每一组。用户提示词与原脚本的明显冲突在一次输入整理中发现并澄清；审查依据始终是原脚本。缺失关键动作、顺序或必要切镜仍照常判定问题，不因提示词漏写而放宽。

首次多图试生成必须检查真实镜头对应，普通多图能力不保证按脚本切镜。未生成邻组导致边界暂缺不等于本组失败；先记录局部观察，继续独立组生成，边界就绪后补核对。顺序、必要硬切、漏镜、字幕均属于视频审查，不能因仅交付图片而免查。
