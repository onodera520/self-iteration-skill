# 视频来源分组与实证聚合

## 默认：用户视频来源组

审查后的剧情合并、短段复核、锚点保护和两表渲染由现有规则工具一次完成，不重复启动 LLM 复述或重新裁决已有有效取舍依据。来源变化或确有剧情依据缺项时才回到相应步骤。工具只在当前操作内复用完整上下文和证据校验，返回前重验全部依赖文件内容；不改变指纹值、版本规则或必要漏镜阈值。

用户提供视频、脚本和资产图。一份视频登记一个来源组及其应覆盖的连续脚本范围；来源组不是最终聚合，不运行初始 --apply，本规划步骤不调用 API；审查后的授权返修见 auto-repair.md。

已有视频的 PROFILE.json 可写 `{}`；不用模型配置的时长、图片数或成本限制。新版聚合固定要求每组计划总时长4–15秒、每组≤12镜。计算使用十进制求和，4秒与15秒均可通过，低于或超过边界均不可通过。原始镜头对应 Clip，最终聚合组对应 Shot，不改变原镜号或必要切镜。

## 计划时长与一次批量剧情整理

复用每镜 duration（秒），增加 `duration_source: {"kind":"script","ref":"S01 原文 3 秒"}`。脚本未给时长，代理根据动作和剧情提出建议，用 `kind: inference`，ref 写明建议依据。不得把建议写成脚本原值或视频实测值。实际时间戳只定位，不用来代替计划时长，也不比较实际与计划的偏差。所有镜头都计时，包括漏镜、待检查及 ai_fill。

在原有完整脚本的一次整理中填写 event 和 narrative_plan，组级审查同时核对，不增加逐镜判断。event 是初步自然段；可跨 scene_id，不改变 continuity_id 或状态继承。新事件编号不再阻止自然承接的相邻段合并。同一事件编号的非相邻镜头不跳序合并。

只在同一 Beat 内聚合。输入明确提供 Beat 划分时，每镜填写 `beat: {"id":"B01","source":{"kind":"script","ref":"原文第一段 Beat"}}`；显式划分需要覆盖全部镜头，不能部分填写。由已提供段落对应关系整理编号可用 inference 并说明出处，不另造剧情边界。未提供 Beat 时，全脚本视为一个隐式 Beat；不得把 event.id 当作 Beat，否则会阻止自然段二次合并。Beat 仅限制聚合范围，不改变状态继承；非相邻同 Beat 不能跳过中间镜头合组。

narrative_plan 使用一条块级来源，boundaries 按原镜序覆盖每个相邻位置。merge_allowed 仅表示剧情允许承接，仍须满足时长、镜数、整段复杂度及来源边界检查；strength 为承接强度 0–3，越大越强。safe_spans 是一次审查认可生成复杂度可接受的完整连续区间及理由；可复用其子区间，但两个重叠区间不证明并集也可生成。不应把未经判断的全脚本直接填成一个安全区间。

```json
{
  "source":{"kind":"inference","ref":"通读 S01–S03：持钥匙、观察、交接属于同一连续剧情"},
  "boundaries":[
    {"before_shot_id":"S02","merge_allowed":true,"strength":2,"reason":"同一关系下的观察承接"},
    {"before_shot_id":"S03","merge_allowed":true,"strength":3,"reason":"观察后立即交接"}
  ],
  "safe_spans":[{"shot_ids":["S01","S02","S03"],"reason":"同场两人一把钥匙，完整区间只有一次交接，视觉关系稳定"}]
}
```

## 三步完成最终分组，再选择参考图

1. **通读剧情找自然边界。** 景别、视角、运镜变化、局部特写、同一行动推进、即时反应、情绪升级、同一关系内主体切换、余波及短 OS/VO 默认优先合并。外部打断刚出现的第一时间反应、短暂出声或内心判断不单独构成新组。独立新事件、真正目标变化、明确时空跳跃、新主体持续主导或明显复杂度上升才构成切分依据；填写具体原因，不能只写“场景不同”。推门连续走到门外不自动拆分。原自然段已超限制时在内部弱承接处拆分，同等条件取较长合法前段。
2. **强制检查相邻段二次合并。** 只要仍属于同一 Beat 的连续剧情、自然承接、人物/空间/关系/主视觉中心稳定且整个区间复杂度可接受，在15秒及12镜内继续合并。优先强承接，同等条件从前向后。不能停在 event 初分结果，也不能为了减少参考图数量决定剧情边界。
3. **强制复核小于8秒的短段。** 若为前段余波、结果、反应或后段起势、铺垫，优先并入承接更强的一侧，同等优先前组。独立事件、关键转折、必要爆点可保留；受15秒、12镜、整段复杂度、Beat或跨视频边界限制也可保留，但理由必须明确，且保留组仍须≥4秒。8秒只是复核线。二次合并已合到合法最大后，短段仍逐个记录不能再合并的原因。出现不足4秒的尾组时，工具先重排合法的相邻切分位置，例如13个1秒镜头不能输出12+1，可改为9+4；不修改原镜时长、不放松剧情/证据边界。

单镜超过 15 秒时不擅自缩短或删镜，标“需拆分或调整计划时长”。缺时长、缺来源或缺剧情分组依据时，可继续抽帧和审查，但新版聚合标 feasible: false，用 P 编号逐镜占位而非合格 A 组；补齐后重建有效证据绑定与审查。旧结果不能直接升级。

不足4秒的独立事件、过短 Beat 或其他约束冲突若无法合法重排，也标 feasible: false，说明需补充连续内容、拆分或调整计划时长，由用户决定。不得为凑4秒跨独立事件或 Beat、复制镜头、填充新动作、静默延长时长。

自定义聚合规则混乱或意义不明时，以原脚本叙事连贯性兜底；与分镜聚合、剧本分析无关的规则不参与聚合。兜底仍须填写可追溯的剧情依据，不能把未审查区间直接声明为 safe_spans，也不能绕过4–15秒、12镜、Beat、镜序、复杂度或来源证据边界。

## 输出前完整性核对与内部 JSON

工具在可行分组返回前独立核对：所有原镜号按顺序且各出现一次，无漏镜、重复、跳序；各组4–15秒且≤12镜；各组时长等于原镜时长之和；全组总时长等于原脚本总时长；组内不跨 Beat；已执行相邻合并检查及短段复核。漏镜和 ai_fill 同样参与覆盖和求和。

内部沿用 shots[].id/duration/script，分别对应有序 clipList 的 id/duration/content，不再要求 LLM 重写一份数据。aggregation.clipGroupList 按所给 MD 保存同构的机读结果；根节点为一个合法 JSON 对象，不附 Markdown、注释或解释。assetIdList 取该组原镜 asset_ids 的并集，按项目 assets 的原始顺序输出，不推测新资产。示例：

```json
{"clipGroupList":[{"shotId":"shot_1","originClipIdList":["S01","S02","S03"],"totalDuration":5.5,"assetIdList":["girl","boy","key"]}]}
```

聚合无解时 clipGroupList 为空，不把 P 占位当作合格 Shot。JSON 留内部，不新增用户交付文件；最终仍为图片及既定两张 Markdown 表。grouping policy=3，Beat、计划时长、剧情依据及规则版本进入现有指纹链，旧聚合失效后重新核对，不自动升级画面结论。

雨夜例的初分仍可为“林默离开 / 苏晴犹豫决定 / 推门追出”，但最终必须重新检查后两段是否自然承接且合计不超过 15 秒，不能固定输出旧三组。

## 审查后：生成独立聚合与省图建议

一次组级审查同时输出 shot_reviews 和 reference_assessments。逐镜检验独立，不要求全组 PASS 才保留其他已通过镜头。可推导省图的语义判据和字段组合以 [审查决策表](review.md#可推导省图判据与决策表) 为准；审查提供候选，规划在最终分组内作约束裁决，以省去独立图后故事仍可读且无歧义为准，不要求唯一复原画面；也不能把状态差分为零直接等同于可省图。

| 当前依据 | 规则处理 |
|---|---|
| 人物首次出场、关键状态/空间变化、叙事转折、关键结果、必要锚点 | 保留参考图；若必要内容确认缺失，计入 bad_num |
| matched、该镜 PASS、有已通过前后锚点和资产支持，省图后故事可读无歧义、无必要剧情节点 | 可推导省图候选，仍是未验证建议 |
| 完整补查确认 absent、有已通过前后锚点和资产支持、省图后故事可读无歧义且无必要剧情节点 | 可推导省图候选；保留“视频漏镜”结论，不能标检验通过 |
| confirmed absent 且省图会断裂/有歧义或受必要锚点规则保护 | 必要漏镜，需补生成 |
| matched 但逐镜 FAIL | 该镜需重新生成，不计必要漏镜 |
| uncertain、来源失效、证据不足或推导未定 | 待检查，不批准省图，不计必要漏镜 |

在项目副本中运行相邻区间规划，保留组首尾、场景边界、关键结果、未知关键事实和用户锁定图。`ΔI≈0` 不能独自批准省图。ai_fill 的两个依据镜号必须是同来源组中已检验通过且保留图片的前、后锚点，顺序夹住该镜，并在最终同一聚合组内。不得让缺失镜头或其他 ai_fill 互相作为依据。

先完成上述剧情分组，再在固定最终组内减少保留图片数量。分组理由使用具体事件说明、合并依据及短段保留原因。场景变化、关键道具状态、关键动作结果仍保护为必要锚点；纯表演细节、局部手势和普通微表情不因独立出现就保护；同组不等于可省图，也不代表画面检验通过。原镜号、顺序、剧情和必要切镜始终保留。跨来源组聚合须有当前有效边界检查，失败或不确定的边界阻止跨越，即使 event.id 相同也不例外。

结果保存为独立 aggregation，不覆盖来源 groups、版本、抽帧时间和任务。省图结论绑定当前脚本（含 duration、duration_source、beat、event、narrative_plan）、规则版本、资产、视频、匹配、完整补查、依据图和审查指纹；缺失镜头不伪造对应帧证据。来源变化后相关结论失效。

每份来源视频分别统计 missing_required。默认 bad_num >= 2 且必要漏镜 / 应覆盖镜头数 >= 20% 才建议重新生成该视频。已定位的画面错误、可推导漏镜及待检查不计数。比例按原视频应覆盖的镜数计算，不按最终聚合组计算，也不因省图减少分母。结果仅存内部 missing_summary；交付不增加视频结论表。

输出聚合与省图建议，不保证未来 AI 一定复现该画面。所有 ai_fill 标建议/未验证，不启动专项生成验证。展示规则见 [项目约定](project.md)。

## 旧生成模式兼容：只划必要试生成组（默认跳过）

此兼容模式使用 video_input_mode: assets。每组按项目 assets 顺序上传用到的全部资产；图片编号表示资产，不等于镜头编号。根据同场景、同连续事件的相邻区间、模型图片数及时间限制分组。组内每镜仍硬切，不能合并叙事事件或减少镜头。

保留用户时长与画幅；未给定时可提出每镜约 1–2 秒，关键交接适当延长，再核对模型准确限制。单镜资产数仍超限则换合适模型或说明阻塞，不静默丢资产，不为规避限制临时生成独立分镜图。离散时长不兼容时调整方案需明确依据，不能暗改原脚本。

直接使用用户提供的视频提示词，保留原文于 user_video_prompt；单组不自动追加旧版基础提示词或 requirements。多组在 groups[].video_prompt 中保存对应片段，只适配资产编号、区间和模型输入，不另设提示词创作步骤。初始分组或返修拆组完成后再填写各组片段；拆组不会继承整段 video_prompt，避免重复提交全故事。不能将全故事提示词重复用于每一组。用户提示词与原脚本的明显冲突在一次输入整理中发现并澄清；审查依据始终是原脚本。缺失关键动作、顺序或必要切镜仍照常判定问题，不因提示词漏写而放宽。

首次多图试生成必须检查真实镜头对应，普通多图能力不保证按脚本切镜。未生成邻组导致边界暂缺不等于本组失败；先记录局部观察，继续独立组生成，边界就绪后补核对。顺序、必要硬切、漏镜、字幕均属于视频审查，不能因仅交付图片而免查。
